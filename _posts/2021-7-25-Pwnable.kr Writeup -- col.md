> 題目 ssh col@pwnable.kr -p2222 (pw:guest)



## 解題

### src

```c
#include <stdio.h>
#include <string.h>
unsigned long hashcode = 0x21DD09EC;
unsigned long check_password(const char* p){
        int* ip = (int*)p;
        int i;
        int res=0;
        for(i=0; i<5; i++){
                res += ip[i];
        }
        return res;
}

int main(int argc, char* argv[]){
        if(argc<2){
                printf("usage : %s [passcode]\n", argv[0]);
                return 0;
        }
        if(strlen(argv[1]) != 20){
                printf("passcode length should be 20 bytes\n");
                return 0;
        }

        if(hashcode == check_password( argv[1] )){
                system("/bin/cat flag");
                return 0;
        }
        else
                printf("wrong passcode.\n");
        return 0;
}
```



首先，先簡單分析一下原始碼 :

 我們需要在命令行執行 col 程式時，後綴 20個字元( 1 個字元 1 byte)的字串，依照 C 命令行參數的規則，這個字串的位址會存在 argv[1] ( 不熟悉 C 命令行參數的人可以參考這篇  [fd 的 writeup](https://zinwang.github.io/techblog/articles/ctf/Pwnable.kr-Writeup-fd/) )。然後把 argv[1] 送進 check_password()，如果回傳的東西等於 0x21DD09EC，就能拿到 flag 。



而 check_password() 又做了什麼呢? 

```c
unsigned long check_password(const char* p){
        int* ip = (int*)p;
        int i;
        int res=0;
        for(i=0; i<5; i++){
                res += ip[i];
        }
        return res;
}

```



在 check_password 函數第一行的部分發現，他竟然將 p 強行轉成 int 指標存在 ip。

```c
int* ip = (int*)p; // p 是後綴字串的位址
```



繼續往下看，

```c
int i;
int res=0;
for(i=0; i<5; i++){
	res += ip[i];
}
```

20 bytes 除以 5 正是 4 bytes (64 位元 int 大小)，到這裡我們發現，他根本就是把原本是 20 bytes 的字元陣列當作一個整數陣列。

如下圖所示，每四個字元的資料會被當成 1 個 int。

<img src="..\..\..\assets\images\2021-7-25-Pwnable.kr Writeup -- col\data.png" alt="\assets\images\2021-7-25-Pwnable.kr Writeup -- col\data.png" style="zoom:67%;" />



然後這 check_password 就會回傳這五個 int 的和 (res)。

因此，只要能夠構造出一串字元，讓 res 等於 0x21DD09EC，就能拿到flag。





### The Ideas and The Solutions

知道這個程式在幹嘛後，應該也就不難了。

首先，為了省事，讓字元陣列的五個等分都一樣就好了。每個等分都是相同的字串，轉成 int 都是相同的值。

所以說，我們用python 算一下，將 0x21DD09EC 除以五

```python
>>> 0x21DD09EC/5
113626824.8
```

等等......不整除 (≡ε≡；)





#### Solution 1 

不整除.......那就湊吧。

 若是 0x21DD09EC 除以 4 ，可以整除

```python
>>> 0x21DD09EC/4
142033531.0
```



假設 $$x, y$$ 為整數， $$y=4k$$  。 令  $$4 x+y= \texttt{0x21DD09EC}$$ ， 如下圖所示。

<img src="..\..\..\assets\images\2021-7-25-Pwnable.kr Writeup -- col\idea1.png" alt="\assets\images\2021-7-25-Pwnable.kr Writeup -- col\idea1.png" style="zoom:67%;" />

則  $$x+k= 142033531$$。

因為 $$142033531 = 71016765 + 71016766$$，假設 $$x = 71016766，k = 71016765$$，則  $$y = 284067060$$。



Okay! 那我們要如何構造出對的字串對應到各個整數值呢?

首先，我們直接 hex 起來 !! 以 16 進位表示比較方便理解。

 ```python
 >>> hex(71016766)
 '0x43ba13e'
 >>> hex(284067060)
 '0x10ee84f4'
 ```



先看 x 的部分。有些人會說，不就是把整數一個 byte 一個 byte 對應到字元嗎 ? 既然 $$x= \texttt{0x043ba13e}$$ ，那就拆成 0x04, 0x3b, 0xa1, 0x3e 轉成字元就好了。 此話只對了一半，整數資料在記憶體中的排列順序其實是有規則的， 這裡要介紹的是 [Endianness](https://zh.wikipedia.org/wiki/%E5%AD%97%E8%8A%82%E5%BA%8F#%E7%AB%AF%EF%BC%88endian%EF%BC%89%E7%9A%84%E8%B5%B7%E6%BA%90) 的概念。





##### Endianness

Endianness 稱為位元組順序或端序，就是資料在記憶體中排列的順序。常見的順序有 Little-endian 小端序、Big-endian 大端序等等。小端序即將資料的低位放在較小的位址處，高位放在較大的位址處；大端序則反之。因為 int 佔 4 bytes， 所以會被端序影響，而 char 只佔 1 byte 因此不會被影響。

晶片架構選擇使用何種端序其實沒有一定原因，

根據 [維基百科](https://zh.wikipedia.org/wiki/%E5%AD%97%E8%8A%82%E5%BA%8F#%E7%AB%AF%EF%BC%88endian%EF%BC%89%E7%9A%84%E8%B5%B7%E6%BA%90)  :

>在哪種位元組順序更合適的問題上，人們表現得非常情緒化，實際上，就像雞蛋的問題一樣，沒有技術上的原因來選擇位元組順序規則，因此，爭論淪為關於社會政治問題的爭論，只要選擇了一種規則並且始終如一地堅持，其實對於哪種位元組排序的選擇是任意的。

而現今絕大部份的處理器架構如 Intel x86 或 AMD64 等都採用小端序，所以在解題時也不用太煩惱是大端序還是小端序。不過如果想知道如何檢查目前所在環境所採用的端序，可以參考這篇 StackExchang: [How to tell if a Linux system is big endian or little endian?](https://serverfault.com/questions/163487/how-to-tell-if-a-linux-system-is-big-endian-or-little-endian) ，很多大神提供了多種方法。



有了端序的概念，我們就知道要如何排列資料。

因為題目環境是採用小端序，以 x 來說，應該要排成如下圖。

<center> <img src="..\..\..\assets\images\2021-7-25-Pwnable.kr Writeup -- col\4bx.png" alt="\assets\images\2021-7-25-Pwnable.kr Writeup -- col\4bx.png" style="zoom: 80%;" /></center>



由於在 linux 或 unix like 環境上 main function 的參數字串是存在 [call stack](https://en.wikipedia.org/wiki/Call_stack) ( 以下稱 stack ) 上 $$^{1}$$，而 stack 正是從高位址往低位址增長(這個概念很重要)，所以我們構造出的字串便是按照 0x3e, 0xa1, 0x3b, 0x04 的順序填入就可。 而 y 的順序 0xf4, 0x84, 0xee, 0x10。



知道順序是怎麼排的了之後，下一個問題就是如何把整數轉成字元。 

搞了一陣子之後，我才發現 pwnable.kr 的環境中有裝 python (┛`д´)┛       

所以我們只要使用 backtick ``` ` ``` 與一行 python 就能完成任務。 
linux 指令中 backtick ``` ` ``` 所代表的是，先執行 ``` ` ``` 包起來的東西再將輸出給前面的主指令使用，
見 [What does ` (backquote/backtick) mean in commands?](https://unix.stackexchange.com/questions/27428/what-does-backquote-backtick-mean-in-commands) ;
而 python 命令行附上參數  ``-c`` 就能將接在後面的字串當作 python 程式碼執行。 



python2 的方法較為簡略，字串中可用 ``\x`` 表示 16 進位數所代表的字元 (ASCII) :

```shell
./col `python -c "print '\x3e\xa1\x3b\x04'*4 + '\xf4\x84\xee\x10' "`
```





##### Pitfall of Command Line Solution 1 with Python3 

由於 python2 已經停止維護了，所以想做個 python 3 解，結果踩到了一個坑。
本想說應該很簡單，依樣畫葫蘆， 改成 python3 print 的語法就行了。

```shell
col@pwnable:~$ ./col `python3 -c "print('\x3e\xa1\x3b\x04'*4 + '\xf4\x84\xee\x10')"`
passcode length should be 20 bytes
```

但是執行時程式一直報  ```passcode length should be 20 bytes``` ，令人百思不得其解，明明給的字串長度是對的，為何一直說輸入的東西不是 20 bytes ?

直到我用了 xxd 檢查，歐靠! WTF is this ?

 ```shell
 col@pwnable:~$ python3 -c "print('\x3e\xa1\x3b\x04'*4 + '\xf4\x84\xee\x10')"|xxd
 00000000: 3ec2 a13b 043e c2a1 3b04 3ec2 a13b 043e  >..;.>..;.>..;.>
 00000010: c2a1 3b04 c3b4 c284 c3ae 100a            ..;.........
 ```

仔細看，在某些字元後面都接了奇怪的東西，像是 0x3e 後面接了 0xc2 :

```shell
col@pwnable:~$ python3 -c "print('\x3e\xa1\x3b\x04')"|xxd
00000000: 3ec2 a13b 040a                           >..;..
```



原來 python2 的 string 只有 ASCII， 非 ASCII 字元不會被轉換，直接寫入記憶體。但是 python3 string 是 Unicode strings，非 ASCII 字員會以 utf-8 編碼。所以在 python3 中應該使用 Byte strings， 也就是字串前綴一個 b 如  ```b"\x3e\xa1\x3b\x04"``` ; 而且不可使用 print，因為 print 預期會使用 Unicode Strings ，print 根本不鳥那個前綴 b :

```shell
col@pwnable:~$ python3 -c "print(b'\x3e\xa1\x3b\x04')"|xxd
00000000: 6227 3e5c 7861 313b 5c78 3034 270a       b'>\xa1;\x04'.
```



 所以應該要使用 ``` sys.stdout.buffer.write ``` :

```shell
col@pwnable:~$ python3 -c 'import sys; sys.stdout.buffer.write(b"\x3e\xa1\x3b\x04")' | xxd
00000000: 3ea1 3b04                                >.;.
```

這就達到我們要的結果了。

所以 python3 的解就是 :

```shell
./col `python3 -c 'import sys; sys.stdout.buffer.write(b"\x3e\xa1\x3b\x04"*4+b"\xf4\x84\xee\x10")'`
```



這篇 [stackoverflow](https://stackoverflow.com/questions/42884251/why-is-the-output-of-print-in-python2-and-python3-different-with-the-same-string) 的解答寫的分常詳盡，要知道 python3 string 是如何用 UTF8 編碼的可以參考一下。 







> $$^1$$ : 根據 [System V Application Binary Interface](https://wiki.osdev.org/System_V_ABI) 。當程式開始執行時，會最先呼叫 _start (而不是main)，而參數字串是存在初始 stack 上的 information block，詳見 [System V Application Binary Interface AMD64 Architecture Processor Supplement (With LP64 and ILP32 Programming Models) Version 1.0](https://raw.githubusercontent.com/wiki/hjl-tools/x86-psABI/x86-64-psABI-draft.pdf) 第 30, 31頁與[System V Application Binary Interface Intel386 Architecture Processor Supplement Version 1.1](https://raw.githubusercontent.com/wiki/hjl-tools/x86-psABI/intel386-psABI-1.1.pdf) 第19頁。






#### Solution 2

其實我解這題最初的想法是想要達到 Solution 1 一開始的想法，讓字元陣列的五個等分都一樣就好了 ，因為我很懶得湊數字。

<center><img src="..\..\..\assets\images\2021-7-25-Pwnable.kr Writeup -- col\idea2.png" alt="\assets\images\2021-7-25-Pwnable.kr Writeup -- col\idea2.png" style="zoom: 80%;" /></center>

但是 0x21DD09EC 是 568134124，不是 5 的倍數，要讓他變成 5 的倍數，起碼尾數要加 6 才行。

此時靈光一閃， 因為  $$2^1=2,\quad 2^2=4,\quad 2^3=8,\quad 2^4=16,\quad 2^5=32 , \quad2^6=64, \quad2^7=128 \quad...$$  
2 的次方尾數是 2, 4, 6, 8 的循環， 便把腦筋動到 int overflow 上。

int 的 最大範圍是  $$2^{31}-1$$， 只要將一個整數 N 加上 $$2^{31}$$ 就會溢位回到 N。而只要我 $2^{31}$ 多乘個幾次 2 ，一定會遇到尾數為6 ，嘿嘿。
正好，$2^{31}$ 就是 2147483648 (身為一個好寶寶，背下這串也是應該的 ) ，乘一個 2 便是  4294967296，尾數為 6。

所以  568134124 + 4294967296 除 5 便是 972620284，轉成 hex 再用 little-endian 排列就得到 ```'\xfc\x01\xf9\x39'```，我們 python2 的答案就是 :

```shell
./col `python -c "print '\xfc\x01\xf9\x39'*5 "`
```

 

但但但是，我們才不屑用什麼命令行 python 解呢，要是再踩到奇怪的編碼陷阱或者目標環境中根本沒有裝 python， 這種方法根本無用 (#`Д´)ﾉ                



所以我們要來介紹一個 pwn 的好工具， pwntools !!





##### Pwntools

pwntools 是一個以 python 開發的模組，用來簡單快速的編寫漏洞利用程式，可以遠端訪問題目程式，並執行接收輸出，是個 CTF的好工具 ，未來打 Pwn 都會常常遇到他。這是 [官方 doc](https://docs.pwntools.com/en/stable/index.html#)， 可參考一下使用方法。



在這裡主要要介紹的是 pwntools 的 p32 函式，p32 函示可以將一個 int 依照 littile-endian 打包成 4 bytes 的資料(4 bytes = 32 bits)，我們就可以不用手動排序。

例如將剛才的 972620284 打包:

```python
>>> from pwn import *
>>> p32(972620284)
b'\xfc\x01\xf99'
```

欸，不要懷疑，```b'\xfc\x01\xf99'``` 就是 ```b'\xfc\x01\xf9\x39'``` ，只是 ```\x39``` 是 ASCII 字元 9 ，所以 python3 print 的時候會被解析出來。

下面這就是 pwntools 的解。

###### Pwntools 解

```python
from pwn import *

x=int((0x21DD09EC+2147483648*2)/5) # 972620284
pl=p32(x)*5 # 五個部分的資料 (Byte strings)

r=ssh("col","pwnable.kr",password="guest",port=2222) # 建立 ssh 連線 col@pwnable.kr, port: 2222, password: guest

p=r.process(executable="./col",argv=["col",pl]) # 執行 ./col 程式並附上參數，記得嗎，argv[1] 才會指到命令行參數
flag=p.recv().decode("utf-8") # p.recv() 接收程式執行的輸出，然後用 decode("utf-8") 解碼存到 flag。 
p.close() # 關閉 proccess p
r.close() # 關閉 ssh 連線
print(flag) # 印出 flag
```
